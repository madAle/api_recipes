# Security specs

Every protection the gem offers has an example in this folder that proves the
abuse case through the public DSL: the example does what an attacker (a user
typing a value, a server answering, a file on disk) would do, and, unless its
row says otherwise, fails when the gem's own code for that protection is
removed. Rows that say "observed" or "covered by http.rb" are not proven that
way. Run them with `bundle exec rspec spec/security`.

Spec files:

| File | What it covers |
| --- | --- |
| `url_injection_spec.rb` | values typed at run time: path parameters, variables, `with(host:)`, headers, parameters sent with every request |
| `dsl_credentials_spec.rb` | credentials through the DSL: owners, `with`, origins, restored and frozen objects |
| `credentials_spec.rb` | the same rules on the request layer, with explicit levels |
| `declarations_spec.rb` | one api declared through modules, subclasses, `extend` and singleton classes |
| `levels_by_declaration_spec.rb` | a level given by one declaration, or written through it, is never read by another declaration of the same api |
| `stale_handles_spec.rb` | an api or an endpoint kept in a variable across a `configure` |
| `redirects_spec.rb` | redirects on the request layer |
| `dsl_responses_spec.rb` | redirects, `fill`, `data` and timeout through the DSL |
| `fill_spec.rb` | `Response#fill` with keys chosen by the server |
| `dsl_objects_spec.rb` | what `Api`, `Endpoint` and `Response` show, write and let Ruby do |
| `dsl_logging_spec.rb` | what the logger receives |
| `configuration_spec.rb` | local files, ERB, YAML, refused configurations |
| `openapi_import_spec.rb` | `api_recipes import`: a hostile OpenAPI description and the recipe written from it |
| `portable_recipes_spec.rb` | portable recipes: a hostile recipe or repository, with `recipes_paths`, `install`, `update` and `check` |
| `variables_in_options_spec.rb` | a `{variable}` in the protocol, the port, the verb and the other options of a request |
| `project_commands_spec.rb` | the commands that read the files of a project: `upgrade` with no argument and `convert` |

## Values put in the URL and in the headers

| Risk | Protection | Spec | Example |
| --- | --- | --- | --- |
| A parameter with `/`, `..` or `?` reaches another endpoint | each value is one encoded segment | `url_injection_spec.rb` | `keeps the path parameter ... inside its segment` (one per hostile value), `sends a slash of a path parameter as %2F and keeps the segment count` |
| A path parameter that is `nil`, empty, `.` or `..` | refused, not neutralized | `url_injection_spec.rb` | `refuses, and does not neutralize, the values that name no segment or the current or parent one` |
| A `*name` placeholder used to climb | each piece encoded; empty, `.`, `..` pieces refused | `url_injection_spec.rb` | `rejects the splat value ...`, `rejects the splat value ... that has an empty, current or parent piece`, `encodes each piece of a splat value` |
| A variable in the host name moves the request to another server | restricted character set for the host position | `url_injection_spec.rb` | `rejects the host variable ...` |
| A variable in `base_url` climbs or leaves its segment | the value is one encoded segment | `url_injection_spec.rb` | `keeps a base_url variable inside its segment` |
| A variable in the `path` of an endpoint climbs, leaves its segment or adds a query string | the value is one encoded segment; `nil`, empty, `.` and `..` are refused | `url_injection_spec.rb` | `a variable in the path of an endpoint keeps the value ... inside its segment` (one per hostile value), `... refuses, and does not neutralize, the values that name no segment or the current or parent one` |
| A variable in a value of `default_params` adds a parameter, a header or leaves the query | covered by http.rb, which encodes the name and the value of every parameter: the gem gives it pairs, never text | `url_injection_spec.rb` | `a parameter sent with every request sends the value ... as the value of one parameter` (one per hostile value) |
| `with(host: ...)` or `api :x, host: ...` with a malformed value | same validation as the `host` of the configuration | `url_injection_spec.rb` | `rejects the host ... in with and in api`, `refuses a protocol or a port that is not one in with and in api` |
| A value adds a header (`default_headers`) | line breaks and control characters refused | `url_injection_spec.rb` | `refuses a header value that would add a header` |
| A variable used in a header adds a header | line breaks and control characters refused in variables | `url_injection_spec.rb` | `refuses a variable that adds a header through default_headers` |
| A credential with a line break adds a header | refused by the gem before http.rb sees it | `dsl_credentials_spec.rb` | `a credential with a control character is refused before it is sent, without showing it` |
| The form of a host is checked, not its owner | stated limit of the gem | `url_injection_spec.rb` | `does not decide whose a well-formed host is` |

## Credentials

| Risk | Protection | Spec | Example |
| --- | --- | --- | --- |
| The token of one user used for the request of another | chain instance, class, global; `with` keeps nothing | `dsl_credentials_spec.rb`, `credentials_spec.rb` | `does not use the token of one object for the request of another`, `lets an instance with no token of its own take the shared one, and never the token of a sibling`, `keeps nothing from with`, `refuses to store a credential on an object returned by with`; `gives each object its own token`, `walks instance, class, global` |
| A client with no token acts with the shared one | an assignment closes the lookup, also `nil` | `dsl_credentials_spec.rb`, `credentials_spec.rb` | `sends no token for a client whose token was set to nil, although a shared one exists`; `stops at an explicit nil instead of using the shared token` |
| A shared token sent to a different host | a credential is valid for the origin of the level that set it | `dsl_credentials_spec.rb`, `credentials_spec.rb` | `does not send a shared token to another host, protocol or port selected with with`, `does not send a token to a host a variable selects, when the token was set at a farther level`, `does not send a token whose own level cannot tell the host a variable selects`, `does not let a class that changes the host receive the global token`, `sends a token set together with the destination, and only to it`; `does not send a token to an origin it was not set for`, `does not send a token over another scheme`, `binds a token to the host a variable selects`, `binds a class token to the host the class selects, not a variable of an object of a subclass` |
| An api or an endpoint kept in a variable across a `configure` that moves the host sends the credential of a level to the old host | the origin a level credential is bound to comes from the configuration in force, not from the tree the object was created with; the request raises `CredentialOriginMismatch` and nothing is sent. A `configure` that does not move the origin changes nothing, and a credential given with `with` belongs to the chain | `stale_handles_spec.rb` | `does not take a credential of the global api to the host of the old configuration`, `does not take a credential of an object or of a class to the host of the old configuration`, `does not take a credential to the old host when the api is no longer configured`. `keeps sending the credential when the configure does not move the origin` and `still sends a credential given with with, which belongs to the chain` guard what must keep working: they pass without the protection |
| The token or a variable of one user leaves with the request of another, because code that serves several users assigned it to a level that every thread shares | the level of the application is in the registry that `configure` swaps in, and the level of a class or a module is in its declaration: both are given where the application starts, by `config.values` (inside the block of `configure` only) and by the options of `api`. The writers of an api raise on them, also for a class that answers that it is not one, and work on an object only. Nothing stores a level on a class or a module, and one put there by force is not read. Variable values are kept as text, so an object given as a value cannot change later | `dsl_credentials_spec.rb`, `credentials_spec.rb`, `levels_by_declaration_spec.rb`, `spec/unit/level_spec.rb` | `what every thread shares cannot be assigned: the writers work on an object only`, `... cannot be assigned by a class that says it is not one`, `... takes values inside the block of configure only, and a configure that gives none keeps those in force when it ends`, `... holds its variables as text: an object that could change afterwards is refused, at every level`, `... keeps the level of a class for an endpoint held across a reset!`; `reads no level left on a class or a module that did not declare the api`; `... does not read the level of a module included next to the declaring module`; `refuses to write a set on a class, a module or the ApiRecipes module`. `keeps the value of each thread apart, given to with or to an object of its own` (`spec/integration/path_variables_spec.rb`) guards what must keep working |
| A request that starts while `configure` runs goes to the host of the new configuration with the credential of the old one | the descriptions and the values of the application are in one immutable registry, replaced with one assignment; a request reads its levels and the registry once, and binds each credential to the origin that the same registry gives | `stale_handles_spec.rb` | `never pairs the host of a new configuration with the credential of the old one while configure runs` |
| A second declaration of an api sends a token elsewhere | a level (credential and variables) belongs to the declaration that gave it, or through which an object wrote it: a request served by another declaration of the same api never reads it, whatever `include`, `extend` or `prepend` did before or after the first request. The refusal of a second declaration in one class hierarchy is a clearer error, not the protection | `levels_by_declaration_spec.rb` | `does not send the credential of a module included into the module in use`, `does not send the credential of a module included into the superclass`, `does not send it from an endpoint built before the include and run after`, `does not send it from an endpoint built before the include, in the other direction`, `does not send the credential of a module included into a declaring class`, `does not send the credential of a module included into the superclass of a subclass already used`, `does not read the level of a module included next to the declaring module`, `does not read the level of a superclass for the module a subclass includes`, `does not read the level of a superclass for the declaration of a subclass`, `does not read variables written through another declaration`. The clearer error, in `declarations_spec.rb`: `refuses an object extended with a module that declares the api of its class again`, `refuses a subclass that includes a module declaring the api of its superclass`, `refuses an object extended with two modules that declare the same api`, `refuses a declaration on a singleton class` (refused when `api` is called, before any request, so no use-time check is involved); `does not send the global credential to the host of a class tree`. The clearer error, in `levels_by_declaration_spec.rb`: `keeps the class credential for the class and refuses the prepended declaration`, `does not send what an object wrote through one declaration with a request that another declaration serves` |
| An object restored from a serialized form acts with a credential | the container never writes its value; a restored one means "no credential", also for the other apis of the object after a write on one of them | `dsl_credentials_spec.rb`, `levels_by_declaration_spec.rb` | `sends no credential after a Marshal round trip`, `sends no credential after a YAML round trip`, `sends a restored credential container as no credential, whatever the form`; `sends no credential from a restored object, and inherits none`, `keeps every other api of a restored object without credential after a write on one of them` |
| A frozen client object | assignment refused, `with` still works, nothing shared | `dsl_credentials_spec.rb` | `refuses to store a credential on a frozen object, which can still send one with with` |
| A credential in a log | no query string, header or body in any line, secrets in every place | `dsl_logging_spec.rb` | `puts no secret in the debug lines and in the printed urls` (header, query and default auth), `puts no secret in the debug lines for a basic_auth credential`, `puts no secret in the log of a request that fails`, `puts no secret in the log when the configuration is refused`, `puts no value in the upgrade warnings, and nothing about the request` |
| A credential in `inspect`, `to_s`, `pp` or `definition` | a dedicated `inspect` on `Api`, `Endpoint`, `Response`, the definitions, `Configuration` and the internal objects that hold a value, which `pp` uses too; `to_s` is Ruby's own (class and address) or the same text, except for a `Response`, whose `to_s` is the body; `definition` holds no credential | `dsl_objects_spec.rb`, `configuration_spec.rb` | `shows no option, header, credential or query whatever way they are printed`, `holds no credential in the definition, whatever way it is read`, `does not let an endpoint named inspect hide the safe inspect`; `never shows a credential, whatever is inspected` |
| A header value or a variable value shown when the configuration is printed (a console, an error tracker that captures `config`) | `Configuration` shows only the names of the apis in `inspect`, `to_s` and `pp` | `dsl_objects_spec.rb` | `shows no header and no variable value when the configuration is printed` |
| A header value written when a definition is serialized | a definition refuses `Marshal.dump` and `YAML.dump`; its JSON is `to_h`, where the values of `default_headers` are `[FILTERED]`. The reader `default_headers` returns them: that is its purpose | `dsl_objects_spec.rb` | `does not write the header values of a definition when it is serialized` |
| A value of `default_params`, or of the headers and parameters of an endpoint, shown or written with a definition | `to_h`, the JSON, `inspect` and `pp` of a definition show every such value as `[FILTERED]` or not at all; a definition refuses `Marshal.dump` and `YAML.dump`. The readers `default_headers` and `default_params` return them: that is their purpose | `dsl_objects_spec.rb` | `shows and writes no value of default_params, nor of the headers and parameters of an endpoint` |
| A value of `default_params` in a log | no query string in any line | `dsl_logging_spec.rb` | `puts no secret in the debug lines and in the printed urls`, `puts no secret in the log of a request that fails` (the configuration of these examples has `default_params` and the headers and parameters of an endpoint) |
| A header of the request with a line break makes http.rb raise an error that contains the value | the `headers:` of a request are checked before sending: they must be a Hash, a list of pairs or `HTTP::Headers`, and a name or a value that is not valid text or has a control character (a tab inside a value is allowed) raises `ConfigurationError`, which names the header and never the value | `dsl_objects_spec.rb` | `refuses a header of the request with a control character before sending, without showing its value`, `refuses headers of the request that are not a Hash, a list of pairs or HTTP::Headers, without showing them`, `refuses a header of the request whose name or value is not valid text, without showing its value`. `accepts headers given as a Hash, as pairs or as HTTP::Headers, and a tab inside a value` guards what must keep working |
| A credential written when the owning object is serialized | `Api`, `Endpoint` and `Response` refuse every serialization (YAML, Marshal, JSON, `as_json`, `to_json`). For a `Response`, `Marshal.dump` also fails on a Proc inside the http.rb response, so `marshal_dump` and `as_json` are proven by calling them directly | `dsl_objects_spec.rb` | `refuses every serialization of an Api and of an Endpoint`, `refuses serialization, because the http.rb response holds the request with the credential`, `refuses marshal_dump and as_json on their own, and points to data`, `refuses to_json, alone and inside another structure` |
| A credential in an error message | the value never enters a message | `dsl_credentials_spec.rb`, `configuration_spec.rb`, `dsl_objects_spec.rb` | `a credential with a control character is refused before it is sent, without showing it`; `does not put a credential with a line break in an error`; `an error about the response carries no credential, query, header or body in its message` |
| A credential in the query ends up in `url` | `url` never has a query string; the parameter is added when the request is sent | `dsl_objects_spec.rb` | `keeps the credential sent in the query out of url, and adds it only when the request is sent` |
| `default_params` take the place of the credential sent in the query | a configuration whose `default_params`, on the api or on an endpoint, name the parameter of `auth.name` is refused, and so are the options of a class that name it; when `with` gives a parameter with that name, the credential is the last parameter and the only one with its name | `dsl_credentials_spec.rb`, `spec/integration/default_params_spec.rb` | `a credential sent in the query cannot be replaced by default_params: the configuration that names its parameter is refused`, `... is the only parameter with its name, and the last, when with gives one with that name`; `refuses, when the class is declared, default_params that name the parameter of the credential of the api` |
| A header of the api or of an endpoint with the name of the header that carries the credential | observed: the credential is set after the default headers and replaces a header with its name, whatever the case. It follows from the order in which the request is built, so no single line can be removed to prove it | `dsl_credentials_spec.rb` | `sends the credential, not a header of the same name that the api or an endpoint writes, whatever its case` |
| A credential in the query visible from `response.uri` or the request | `uri` omits it; `Response` does not expose the request | `dsl_objects_spec.rb` | `a response omits the credential sent in the query from uri`, `a response does not expose the request and does not show it in inspect` |
| A response body with personal data in the error message | the body stays on `error.response` | `dsl_objects_spec.rb` | `an error about the response carries no credential, query, header or body in its message` |
| A redirect forwards the credential to another server | no redirect unless asked (http.rb's default, observed); with `follow`, `Authorization`, the header named by `auth`, `Cookie` and a query credential are dropped when the origin changes and not given back. http.rb 6 itself drops `Authorization` and `Cookie` across origins: the examples that fail without the gem's code are the ones about the header named by `auth` and the query credential, and about not giving them back | `dsl_responses_spec.rb`, `redirects_spec.rb` | `a redirect is not followed unless the request asks for it`, `does not take the credential, the header named by auth or the cookie to another origin`, `does not take the header named by auth to another origin, nor give it back on the way home`, `does not take a credential sent in the query to another origin`; `drops the credential and the cookies when the redirect leaves the origin`, `drops the header named by auth`, `drops the credential when only the scheme or only the port changes`, `does not give the credential back after a redirect out of the origin and back`, `does not carry cookies along the chain, whoever set them`, `does not repeat a credential sent in the query to another origin` |
| A `follow` value that http.rb would take as it is | only `true`, `false`, `nil` or a Hash of `strict`, `max_hops`, `on_redirect`, checked before sending | `dsl_responses_spec.rb`, `redirects_spec.rb` | `a redirect refuses a follow value that http.rb would take, before anything is sent`; `refuses any follow value other than true, false, nil or a Hash, with or without a credential`, `refuses follow options that http.rb would refuse, before sending anything` |
| A redirect to an address that http.rb reads only with the optional addressable gem raises `LoadError`, which a plain `rescue` does not catch | that `LoadError` becomes `ApiRecipes::InvalidUrl`, without the address; any other `LoadError` passes | `redirects_spec.rb` | `raises InvalidUrl instead of LoadError, without the address`. `leaves any other LoadError as it is` guards what must keep working: it passes without the protection |

## Answers of the servers

| Risk | Protection | Spec | Example |
| --- | --- | --- | --- |
| `fill` calls a setter chosen by the server (`admin=`, a private method) | public writers only, keys that are plain attribute names, `only:` and `except:` in any form | `dsl_responses_spec.rb`, `fill_spec.rb` | `fill calls only the public writers that match a plain attribute name`, `fill limits a list of objects with only and except, in every form`, `fill ignores what is not an object or a list of objects`; `never calls a private writer`, `skips keys that are not plain attribute names`, `only and except given in different forms` |
| An answer that never arrives | `timeout` always set, 3 seconds by default; a value that would remove the limit is refused | `dsl_responses_spec.rb` | `sets a timeout of 3 seconds on every request, and no request has none`, `refuses a timeout that would remove the limit, and nil falls back to the default` |
| A body read as Ruby objects | `data` uses only the http.rb parser of the declared type | `dsl_responses_spec.rb` | `data never builds Ruby objects from a body`, `data does not read a type that http.rb has no parser for, and so never reads YAML`, `data does not read YAML even when the type is forced with mime_type` |
| An implicit conversion (`to_ary`, `to_str`, `encode_with`, ...) changes what Ruby does with an object | no method is generated for these names; the endpoint stays reachable with `[]` | `dsl_objects_spec.rb` | `does not change how Ruby treats the parent of an endpoint named after an implicit conversion`, `still reaches an endpoint with such a name with [] and sends its request` |

## Local configuration

| Point | Protection | Spec | Example |
| --- | --- | --- | --- |
| ERB is code: evaluated only for the files of `apis_files_paths` | no ERB anywhere else (observed: no code path evaluates ERB elsewhere, so no example fails by removing a protection) | `configuration_spec.rb` | `evaluates ERB in the files of apis_files_paths and nowhere else`, `never evaluates ERB found in a value of apis_configs or in a response` |
| YAML is always read safely | `YAML.safe_load`, no Ruby objects | `configuration_spec.rb` | `does not build Ruby objects from YAML`, `reads YAML anchors and aliases without building objects, and refuses other tags`, `refuses a file that is not a mapping, is empty or is not UTF-8, without showing its content` |
| `verify_with` calls a method, even a private one, of the calling object | allowed only in local sources, `api` and `with` | `configuration_spec.rb` | `lets verify_with call a private method of the calling object, given in api or in with` |
| A `*.recipe.yml` passed to `apis_files_paths`, where it would be evaluated with ERB | refused, whatever the case or the link, and its ERB is not run: a portable recipe goes in `recipes_paths` | `configuration_spec.rb` | `refuses a file named *.recipe.yml in apis_files_paths, whatever the case and the link, and does not run its ERB` |

Also covered: a configuration that is refused
before anything is built (a Hash that contains itself, a YAML alias to its own
mapping, an option given as a String and as a Symbol, names that are empty or
have control characters or invalid encoding, a placeholder in `base_url`, a
host with a character a host cannot have), and the previous configuration
being kept (`configuration_spec.rb`, `a configuration that is refused before
anything is built`).

## Importing an OpenAPI description

The description comes from someone else. The recipe written from it is then
loaded as a local file, where ERB is evaluated.

| Risk | Protection | Spec | Example |
| --- | --- | --- | --- |
| The description makes the importer read another file or download something | only a `$ref` inside the file is followed; any other is an error; one file is opened, the network is never used | `openapi_import_spec.rb` | `a $ref never makes the importer open another file or use the network` |
| A `$ref` that goes round in a circle, or a chain of thousands of them | a circle is an error; so is a chain of more than 64. The schemas, which refer to themselves by design, are never walked | `openapi_import_spec.rb` | `a $ref that goes round in a circle is an error, not an endless loop`, `a $ref that is the first of a very long chain is refused, instead of being followed for minutes` |
| A title, an `operationId` or a parameter name with line breaks adds keys to the recipe | a comment is one line: control characters, every kind of space and line separator (also U+2028, U+2029 and U+0085) and the characters that hide or reverse text become one space; every name and value is written by the YAML generator; the text is read back and compared with the data before it is returned | `openapi_import_spec.rb` | `free text of the description with line breaks never adds a key to the recipe`, `free text of the description with the line separators of Unicode never adds a key to the recipe`, `free text of the description that hides or reverses text is removed from the comments`, `free text of the description is checked again after writing: a recipe that does not read back as intended is not written` |
| Text of the description with `<%` becomes code when the recipe is loaded | `<%` and `%>` are removed from comments; in a value they are an error that says where; the text written never contains `<%` | `openapi_import_spec.rb` | `free text of the description with ERB is removed from the comments, and loading the recipe as a file runs nothing`, `free text of the description with ERB split so that removing a part leaves another is still removed`, `a value of the recipe with ERB in ... is refused, and the message says where` (one per place), `a value of the recipe is never built by the importer from a description of ERB in a parameter name` |
| A value with a line break starts a new line of the recipe | a control character, U+2028 or U+2029 in a name or a value is an error; so are binary data (`!!binary`) and a name longer than 1000 characters, which YAML would not read back | `openapi_import_spec.rb` | `a value of the recipe with a line break is refused`, `a value of the recipe that is binary data, or a name too long for YAML, is refused with a message` |
| Endpoint names that are not valid | reduced to letters, digits and `_`; the real segment stays in `path` | `openapi_import_spec.rb` | `writes endpoint names made only of letters, digits and underscores` |
| A YAML description that builds Ruby objects | read with `YAML.safe_load`: plain data and dates only | `openapi_import_spec.rb` | `refuses a description with a Ruby object` |
| A small YAML description that describes a huge structure through aliases | refused while the text is parsed, before any object is built: aliases that together stand for more than ten million values (counted without expanding them), a key that is not plain text, a nesting deeper than 200 levels. Below that limit an alias is the same object, never a copy, and the importer never turns a mapping or a list into text | `openapi_import_spec.rb` | `refuses a description whose aliases describe more than ten million values`, `refuses a key that is an alias of a huge structure, instead of computing its hash for ever`, `never turns a mapping or a list of the description into text, wherever it is`, `reads a description that says a lot with YAML aliases, within the limit` (guards what must keep working) |
| Text of the description, or of a file of the project, written into a recipe through the calls that `--calls` adds to the comments | a call is made from the tree of the recipe just written and checked, never from the description; one that holds anything but names of endpoints and of parameters is not written; the writer of `import` keeps it on one line without `<%`; the text with the calls is read back and compared with the data, as every text these commands write | `openapi_import_spec.rb` | `the calls written beside the endpoints hold only names of endpoints and of parameters: anything else is not written`, `are written on one line each, without ERB, by the writer of import`, `leave the recipe as it is without them, also from a hostile description` |
| A description made to print without end, or to make the command fail with the text of a Ruby exception | at most 100 warnings are shown, then their number; one warning for each path that cannot be written, not for each operation; what the importer did not foresee is answered with one line and exit code 1 | `openapi_import_spec.rb` | `never prints megabytes of warnings`, `answers a defect of its own with a message, never with a stack trace` |

## Portable recipes

A portable recipe is written by someone else. These rows cover the file loaded
with `recipes_paths` and the commands `install`, `update` and `check`. The
examples run the commands against a Git repository in a temporary folder; the
`file://` address is accepted there only because the spec helper replaces a
constant.

| Risk | Protection | Spec | Example |
| --- | --- | --- | --- |
| Code inside the recipe | a file of `recipes_paths` never goes through ERB, and neither does what the commands read; text with `<%` is refused, so it cannot wait for the day the file is given to `apis_files_paths` | `portable_recipes_spec.rb` | `code inside the recipe is never run by configure: a file of recipes_paths does not go through ERB`, `... is never run by install, update, check and routes, with or without --erb`, `... cannot wait in the file for the day it is given to apis_files_paths: text that ERB would run is refused` |

## What the gem does not do

The application must:

- Not pass to `with(host:)`, or to a variable that is the whole host, a value
  chosen by an end user. The gem checks the form of a host name (letters,
  digits, `-`, `_`, `.`), not whom it belongs to. A request to a well-formed
  host chosen by an attacker is sent, and the credential is not sent to it only
  if it was set for another origin (`does not decide whose a well-formed host is`).
- Treat `original_response` as sensitive: it holds the request, with a
  credential sent in the query.
- Keep `follow` off for requests it does not need to follow, and not give
  `on_redirect` a hook that sends the credentials elsewhere.
- Protect its own configuration files: ERB in `apis_files_paths` runs as code.
- Read a change to `recipes.lock` as a change to the code: `update` connects to
  the address written there, with the keys and the credentials of whoever runs
  it. The command says the address first, and does not judge it.
- Know that over `ssh` the program `ssh` talks to the terminal by itself: what
  it asks, and what a server makes it ask once its key is trusted, does not
  pass through the command. A server that accepts the connection and then
  stops answering keeps the command waiting until it is interrupted: over
  `https` `git` gives up after 30 seconds without data, over `ssh` the limits
  are those of the `ssh` configuration (`ConnectTimeout`, `ServerAliveInterval`).
- Treat every value of a response as untrusted: `fill` writes the public
  attributes that match a key, so `only:` is the list of attributes a server may set.
- Decide how long a credential lives and where it is stored: the gem keeps it in
  memory, per object, and never writes it.
- Read what `api_recipes install` and `api_recipes update` show before answering
  yes. The gem checks the form of a recipe, not whose host it names: a recipe
  that sends the credential to a well-formed host of an attacker is installed if
  you accept it. `--yes` accepts without showing the question.
- Version the installed recipes and `recipes.lock`, and review their changes like
  code. The lock makes a change visible and stops the application; it does not
  stop someone who can change both the file and the lock.
- Trust a repository of recipes as far as it trusts whoever can push to it. A
  tag can be moved: the commit in `recipes.lock` says what was installed, and
  the checksum says what is loaded.
- Know that `git` runs with its own configuration: its credential helper is what
  lets `install` read a private repository, and it downloads the whole commit,
  not only the file of the recipe, into a temporary folder.
